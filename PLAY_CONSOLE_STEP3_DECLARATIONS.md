## Data Safety — draft answers to use after validating the production build

The app uses Firebase Authentication, Firestore, Storage, Cloud Functions and Messaging dependencies; it also sends payout information to RazorpayX. The app source and its privacy-policy draft show these data flows:

| Data category | Data handled | Proposed purpose | Collection / sharing notes |
|---|---|---|---|
| Personal info | Name, phone, email, address, WhatsApp number, account identifiers | Account setup, verification, support, service updates | Collected by Shiv Agency; Firebase supplies account/database services; payout contact details may go to RazorpayX |
| Personal info / sensitive identity | PAN number/image, Aadhaar last four digits/image, verification selfie | Registration/KYC, fraud prevention, payout eligibility | Highly sensitive. Confirm which fields and files are actually collected in the Play build and disclose accurately |
| Financial info | UPI ID/VPA, payout recipient name/phone, payout reference/status | Fulfil UPI reward redemption and provide support | Shared with RazorpayX to execute payout; not payment-card data |
| Financial activity | Points balance, purchase/bill records, points ledger, referral/reward/redemption records | Calculate rewards, reconcile points, prevent fraud, fulfil redemption | Stored in Firestore; includes points converted to UPI payouts |
| Photos and videos | Selfie, PAN and Aadhaar images | Account/KYC review | Uploaded to Firebase Storage |
| App activity / other | App interactions, notification token and basic diagnostics if generated by SDKs | Service operation, requested notifications, reliability | Firebase Messaging SDK is included; validate actual runtime SDK collection for the release build |

For each applicable data type in the form, confirm whether it is collected, shared, processed ephemerally, required/optional, and encrypted in transit. The repository shows Firebase and RazorpayX flows, but does not prove every SDK runtime behavior or transport/security setting. Do not mark data “not collected” solely because a field is optional or handled by an SDK.

**Likely declarations:** data is collected; account/KYC and payout data are required for relevant account/reward features (optional fields should be stated as such); data is encrypted in transit only after confirming the deployed endpoints/configuration; account deletion is available only after the external page and backend are deployed and verified. Do not claim independent security review.

## Blocking items before completing declarations

1. **Remove the hardcoded demo bypass from the production app.** `LoginScreen.kt` accepts phone `9999999999` and fixed OTP `123456`, then invokes demo login without Firebase verification. This is present in release source and is not gated to debug builds. Build a controlled reviewer login using Firebase test phone authentication or another secure review method.
2. Deploy and verify the privacy policy and account-deletion pages; verify the deletion callable and retention behavior work in production.
3. Confirm the actual support contact, intended audience/age range, and a secure reviewer account with test instructions.
4. Confirm the exact runtime data collected by Firebase SDKs in the release artifact and whether all relevant transmissions are encrypted in transit.
5. Sign in to Play Console, select the production app, inspect existing answers, then complete and review every form. Do not certify declarations that have not been verified against the production build and operating practices.

## Evidence inspected

- Android manifest permissions: Internet, network state, camera, biometrics, notifications; no location, contacts, SMS, or call-log permissions.
- Android app dependencies: Firebase Auth/Firestore/Storage/Messaging/Functions, CameraX, ML Kit face detection, Play Services Auth; no ad SDK listed.
- Registration screen requests contact details, address, and selfie. App/model and redemption/backend paths reference PAN/Aadhaar KYC and UPI payout.
- `functions/index.js` implements RazorpayX UPI payout and account-deletion handling.
- `admin/src/pages/PrivacyPolicyPage.tsx` and `DeleteAccountPage.tsx` contain draft public pages; live deployment was not verified.
- `android/app/src/main/java/com/shivagency/rewards/ui/screens/login/LoginScreen.kt` contains the hardcoded demo bypass.
